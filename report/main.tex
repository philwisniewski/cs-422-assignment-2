\section{iPerf Throughput Application}
\subsection{Overview}

Reversed \texttt{iperf3} from the source \href{https://github.com/esnet/iperf}{here} with AI assistance. The iperf3 client is in \texttt{iperf3\_client.py} with the wrapper handling destination selection in \texttt{run\_experiments.py}.

Each \texttt{iperf3} test consists of these phases:

\begin{enumerate}
  \item \texttt{resolve / control\_connect}: DNS resolution and creating the control connection. The server may send \texttt{ACCESS\_DENIED} to refuse the test.
  \item \texttt{cookie}: The client sends a cookie, which is 36 characters drawn from the lowercase letters and digits. This will allow the server to link the data connection to this ctrl connection.
  \item \texttt{param\_exchange}: Server requests and client sends JSON parameters such as protocol, test duration, number of parallel streams, size of each write buffer, number of bytes and blocks (we set these to 0, so the test ends only when time runs out), and congestion control algorithm. We do not send the congestion parameter because we don't want the server to fail to select a certain algorithm and abort the test as a result.
  \item \texttt{create\_streams / data\_connect}: the client creates the data connection and sends the cookie over it. Our client does so after setting the congestion control algorithm.
  \item \texttt{test\_start / test\_running / test\_end}: The test. Our client generates a block of random data. Then, every interval (default 0.2s), it logs some statistics from the data socket (see section \ref{sec:tcp-stats}, and tries to send another block over the data connection. The server does not send any data back, only ACKs. 
  \item \texttt{exchange\_results / display\_results}: The client and server exchange stats like CPU utilization, bytes sent, packets, restransmissions, start/end time, etc.
  \item\texttt{iperf\_done}: Test complete.
\end{enumerate}

When an error is encountered, the client sends a message over the control connection to terminate the test.
